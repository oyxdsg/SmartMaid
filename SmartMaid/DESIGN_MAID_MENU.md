# Smart Maid 游戏内女仆菜单 · 设计规划

> 目标态：**桌宠窗口隐藏后，游戏内菜单要独立承担"和女仆互动"的全部职责**。
> 本文是菜单的信息架构 + 技术方案 + 分期实施规划。实现细节落地面见 `README.md` / `HANDOVER.md`。

---

## 一、现状与问题（要先解决什么）

现在 Shift+右键打开的是 `client/gui/MaidControlScreen` + `gui/MaidControlMenu`：

| 现状 | 问题 |
|---|---|
| 176×88 纯色方框 + 1px 白边（代码绘制） | 不像任何一个 MC 界面，像"调试窗口"；没有女仆的任何视觉元素 |
| 3 个原版灰按钮：坐下/站起、召回、清空目标 | 能力覆盖太少——24 条 AI 指令里能用的只有 2 条，玩家想指挥女仆挖矿/存箱只能打指令 |
| 3 行状态：坐姿、生命、`/ 24` 硬编码、有无目标 | 没有名字、没有饱食、没有当前任务、没有装备概览；`24` 是写死的 |
| 菜单 = `AbstractContainerMenu`，状态走 `ContainerData` | 容器菜单的同步通道只适合槽位；按钮还是另发网络包 → 两套机制并存，扩展性差 |
| 动作走 `MaidCommandPayload(int action)` 枚举（4 个 int 常量） | 每加一个动作就要改协议；而**已有 24 条指令的 JSON 协议 `MaidAIBridge` 完全没被复用** |
| 背包是另一个界面（Shift+E / Shift+右键 → 二级菜单） | 两个入口各开一个窗口，切换要关掉重开，交互断裂 |

**核心判断**：不是"按钮太少"，而是**没有把它当界面来设计**——应该是"女仆的随身手帐"，
而不是"一个能点两下的调试面板"。

## 二、设计原则

1. **一个窗口容纳全部**：状态、任务、背包、对话在一个窗口内用标签切换，不来回开关窗口。
2. **菜单只是 `MaidAIBridge` 的图形前端**：所有按钮 = 一条已有指令（`mine`/`craft`/`chestput`…），
   不发明新协议、不在客户端做业务判断，保证"菜单点的"和"AI 下指令"行为完全一致。
3. **视觉要有"女仆"的在场感**：3D 女仆预览、状态用图标而非纯文字、配色统一，
   避免"一堆原版灰按钮"。
4. **信息分层**：常用动作（跟随/待命/召回/停止）永远 1 次点击可达；任务类走"卡片 → 参数面板"两级。
5. **不做只有玩家能看懂的隐藏操作**：每个按钮的悬停提示要写清"这条会执行什么指令"。
6. **桌宠隐藏后可独立运行**：聊天页在桌宠缺席时降级为"本地指令直通 + 明确提示"，不崩、不静默失败。

## 三、信息架构

窗口尺寸建议 **320×200**（两倍于现状，能放两栏），布局：

```
┌──────────────────────────────────────────────────────────────┐
│ [主页] [任务] [背包] [对话] [设置]        ← 顶部主标签        │
├───────────────────────────────────────────┬──────────────────┤
│                                           │  ✦ 对话           │
│              内容区（随标签切换）           │  ✦ 动作           │
│                                           │  ✦ 帮助           │
│                                           │  ← 右侧竖排入口    │
├───────────────────────────────────────────┴──────────────────┤
│ ♥ 24/24   🍗 18/20   状态：待命(坐下)   任务：无     [跟随][待命] │ ← 常驻状态条
└──────────────────────────────────────────────────────────────┘
```

### 3.1 主页（状态）

- **3D 女仆预览**：可拖动旋转（`InventoryScreen.extractEntityInInventoryFollowsMouse`，与玩家背包里的自己同款），
  直接显示当前皮肤/装备/手持——这是"沉浸感"性价比最高的一块。
- **状态**：生命（心形图标 + 数值）、饱食（鸡腿图标，`MaidFoodData`）、当前行为
  （跟随中 / 待命 / 执行任务 `mine` / 战斗中 / 坐下）。
- **装备概览**：主手 / 副手 / 头胸腿脚的 7 格小图标（`ItemDisplayWidget` 或自绘 16×16 slot）。
- **四个大动作**（1 次点击）：`跟随我`、`待命坐下`、`召回`、`停止当前`。
  → 分别对应 `follow`（取消坐下）/ `sit` / `recall` / `stop|cancel`。

### 3.2 任务（**最大价值页**）

- **正在运行**：任务卡（`当前任务`、已运行 tick、进度描述）+ `取消` 按钮（`status` / `cancel`）。
- **任务格**：按使用频率排布，每格一个图标 + 名称 + 悬停提示：
  | 分组 | 任务 | 指令 | 参数 |
  |---|---|---|---|
  | 战斗 | 护卫 / 攻击 / 喂食 / 进食 | `guard` `attack` `feed` `eat` | 半径、目标实体类型、食物 |
  | 生产 | 挖矿 / 耕作 / 建造 / 收集 | `mine` `farm` `build` `collect` | 坐标(默认准星)、半径、数量、高度 |
  | 物品 | 制作 / 烧炼 / 存箱 / 取箱 | `craft` `smelt` `chestopen+chestput` `chesttake` | 物品 id、数量、槽位 |
  | 移动 | 移动 / 看向 / 破坏 / 放置 / 使用 | `move` `look` `break` `place` `use` | 坐标(默认准星) |
  | 收纳 | 装备 / 收起 / 丢出 / 拾取 | `equip` `store` `drop` `pickup` | 数量 |
- **参数面板**：点任务格 → 右侧展开参数（数字用 stepper / 滑条，坐标默认"准星所指方块"，
  可切"我脚下 / 女仆脚下"）。确认后按 `{"id":..,"cmd":..,"params":{..}}` 发出去。
- **干跑预检**：`craft` 走已有的 `craft_check`，缺料就地提示（不消耗材料），避免"点了没反应"。
- **存箱两步**：`chestopen` 是**异步任务**（回执只表示受理），菜单要在拿回执后轮询 `status` 到 `done`
  再发 `chestput`——这是菜单必须替玩家处理的语义（`HANDOVER.md` §5.1）。

### 3.3 背包

- 直接把现有 `MaidInventoryMenu`（41 格 + 原版背包贴图）**并进这个窗口的一个标签**，
  保留 Shift+E 直接开这一页。
- 建议补上**玩家自己 36 格**（现在没有），这样"给女仆穿装备"不用先丢地上再让她捡。

### 3.4 对话（**桌宠隐藏后的核心页**）

- 上方聊天记录：女仆（左）/ 主人（右）气泡，支持滚动（`AbstractScrollArea`）；
  显示女仆头顶已有的聊天气泡文案（`showBubble` 同源）。
- 输入框：`EditBox`（支持中文输入法）+ `发送` + `按住说话`（⌨/🎤 切换，接桌宠 STT）。
- 快捷短语 chips：`跟着我` `坐下待命` `帮我收进箱子` `去挖点铁` `你在干嘛`。
- **执行链路**（复用现有基建，不重造）：
  ```
  C→S  MaidChatPayload{text}
   S   若桥接可用 → WS 下行新增 chat 消息 → 桌宠 NLU/AI（nlu/router.py + maid_loop）
   S   若桥接不可用 → 文本直接当指令解析（本地降级：命中 24 指令就执行，否则提示"AI 未连接"）
   S→C MaidChatPayload{speaker, text} → 显示气泡；桌宠侧 speak 同时触发语音
  ```

### 3.5 设置

跟随距离（`MaidFollowGoal` 的 3/10 格 → 滑条）、自动拾取、自动战斗、气泡开关、
桥接（桌宠）连接状态与开关。**这是"桌宠隐藏后"玩家唯一的桥接开关入口**。

### 3.6 右侧竖排入口

`对话`（等价于顶部标签，放这里是"高频入口"）、`动作`（11 个 Emotecraft 动作快捷播放，`/maidanim` 已有能力）、
`帮助`（指令速查，等价于把 `/maidtasks` 的帮助做进界面）。

## 四、技术方案

### 4.1 界面分层（关键决策）

| 界面 | 基类 | 理由 |
|---|---|---|
| 女仆主菜单（主页/任务/对话/设置） | **纯 `Screen`**（客户端） | 不涉及槽位就不该挂容器：容器菜单的同步通道/sealed 限制会拖累扩展 |
| 背包标签 | 现有 `AbstractContainerScreen<MaidInventoryMenu>` | 槽位必须服务端权威；以子界面/标签两种方式接入 |

→ 主菜单**不再用 `MaidControlMenu`**；`MaidControlScreen` 重写为 `MaidMenuScreen extends Screen`，
`MaidControlMenu` + `ModMenus.MAID_CONTROL_MENU` 保留（兼容旧存档/旧客户端）或直接下线（需用户确认）。

### 4.2 状态同步

- **客户端本地可读**（女仆实体在客户端存在）：名字、生命、坐姿、位置、装备、手持、调试动画 → 直接读，零同步成本。
- **需要同步**（服务端才有）：`MaidFoodData`（饱食）、`MaidTaskManager`（当前任务/进度）、
  战斗中标志、桥接连接状态、聊天记录。
  → 新增 **S2C `MaidMenuStatePayload`**（打开菜单时发一次 + 状态变化时发；或每 10 tick 节流推送）。
  字段用现成的 `PerceptionModule` 快照即可复用（`self.status` / `inventory` 已经在算），**不必新造一套**。

### 4.3 网络协议

- **动作**：`MaidMenuCommandPayload{String cmd, String paramsJson}` —— 直接把 bridge 的 JSON 原样透传
  （服务端 `MaidAIBridge.execute` 已有全部解析/校验/回执），菜单拿到回执后显示 toast/状态行。
  → 现在的 `MaidCommandPayload(int action)` 只保留 `OPEN_INVENTORY`/`RECALL` 这类**非指令**动作。
- **聊天**：`MaidChatPayload{String text}`（C→S）+ `MaidChatPayload{speaker,text}`（S→C）。
- 回执语义：`ok/state/step/result` 已有；菜单用 `step` 做"已受理/进行中/完成/失败"的进度反馈。

### 4.4 视觉

- 尺寸 **320×200**，1.5× 缩放在 1280×720 下仍可读；标签用 `TabButton`（原版控件，自带 hover/active 语义）。
- 贴图两条路：
  - **(A) 复用 TLM 的 GUI 贴图**（`maid_gui_main.png` / `maid_gui_side.png` / `maid_gui_button.png` /
    `maid_gui_backpack.png` / `maid_gui_task.png`，MIT，本仓库已在复用其皮肤资源）→ 立刻"像个女仆界面"。
  - **(B) 自绘现代扁平风**（圆角卡片 + 半透明 + 主题色）→ 风格更统一但和原版 GUI 有出入，且要自己画素材。
  → 建议 A 打底、用我们的配色覆盖（主色：女仆皮肤同源的暖色），不引第三方依赖。
- 图标：原版 `gui/sprites` 里已有心/鸡腿/经验等 sprite，优先复用；缺的用 16×16 自绘 PNG。

### 4.5 代码结构（预计新增）

```
client/gui/
├── MaidMenuScreen.java          主菜单骨架（标签切换 + 状态条 + 分发）
├── tab/HomeTab.java             主页（3D 预览 + 状态 + 4 大动作）
├── tab/TaskTab.java             任务（卡片网格 + 参数面板 + 进度）
├── tab/ChatTab.java             对话（记录 + 输入 + 快捷短语）
├── tab/SettingsTab.java         设置
├── widget/MaidActionButton.java 带图标/提示/禁用态的动作按钮
├── widget/StatBar.java          生命/饱食条
└── widget/TaskCard.java         任务卡片
client/chat/MaidChatClient.java  聊天记录缓冲（客户端侧）
network/MaidMenuCommandPayload / MaidMenuStatePayload / MaidChatPayload
```

## 五、与桌宠的关系（三阶段）

| 阶段 | 桌宠 | 游戏内菜单 | 成本 |
|---|---|---|---|
| **现在** | 窗口常驻，AI/语音/气泡都在桌宠 | 只有控制面板 | — |
| **阶段 1（本次改造）** | 不变 | 菜单升级为完整界面（主页/任务/背包/设置） | 中 |
| **阶段 2（隐藏窗口）** | 后台常驻（无窗口/托盘），仍是 AI+NLU+STT/TTS 后端 | 菜单新增**对话页**，聊天/语音从桌宠搬到游戏内 | 中（复用 `maid_link` + `nlu`，只加一条 `chat` 消息） |
| **阶段 3（可选：模组自洽）** | 可完全不需要 | 模组内置"文本→指令"直通 + 可选直连 LLM API | 高（要自己接模型/密钥/上下文） |

**建议**：走阶段 1→2，阶段 3 不排期。理由：桌宠已投入了 NLU、拼音匹配、wiki 知识库、
STT/TTS、气泡与动作系统，重写一遍是纯浪费；"隐藏窗口"本来就不要求消灭进程。

## 六、分期实施与验收

| 期 | 内容 | 验收点 |
|---|---|---|
| **N1** | 主菜单骨架（320×200 + 顶部 5 标签 + 右侧竖排 + 常驻状态条）+ **贴图（复用 TLM 女仆风）** + 主页 + 任务页 + 背包并入；动作全部走 `MaidMenuCommandPayload`；对话/设置为占位页（可打开，内容后置） | 每条指令都能从菜单触发，回执与 `/maidtasks` 一致；`chestopen→chestput` 两步自动等待；打开/关闭不影响 AI、战斗与坐下逻辑；1280×720 与 2560×1440 均不越界 |
| **N2** | 主页 3D 女仆预览 + 状态条图标化 + 装备概览 + 任务页参数面板打磨（准星坐标/预检提示） | 视觉与手感验收；`craft` 走 `craft_check` 预检不缺料误报 |
| **N3** | 对话页（接桌宠 `chat`）+ 桌宠窗口隐藏开关 + 语音按钮接 STT | 中文输入法可用；回复进气泡；桌宠未启动时明确提示降级、不崩 |
| **N4** | 设置页 + 动作页（11 个 Emotecraft 动作）+ `H` 键快捷指令盘（轮盘） | 设置项即时生效并持久化（`config/smartmaid/`）；轮盘在准星处呼出 |

**每期都必须**：`gradlew build` → 备份旧 jar → 部署 → 真机看效果（`DEVELOPMENT_ISSUES.md` 2026-09-16 的教训）。

## 七、已拍板决策（2026-09-17）

| 项 | 决策 |
|---|---|
| **一期范围** | **全量 N1**：骨架 + 主页 + 任务页 + 背包并入，动作全部走 bridge 指令（不是只美化现有三按钮） |
| **视觉路线** | **复用 TLM 女仆风 GUI 贴图**（`maid_gui_main/side/button/backpack/task`，MIT；本仓库已复用其皮肤资源），我们只调配色与排版 |
| **页面结构** | **顶部 5 标签（主页/任务/背包/对话/设置）+ 右侧竖排（对话/动作/帮助）**；N1 里对话与设置先做占位页 |
| **对话与 AI 归属** | **阶段 2：桌宠窗口隐藏、进程保留为 AI 后端**（NLU/AI/STT/TTS 全部复用），游戏内对话页通过新增 WS `chat` 消息对接；**不自研模组内置 LLM** |

**实现细节（随手定，可改）**：
- 窗口 **320×200**；缩放到 1280×720 仍可读；图标优先复用原版 `gui/sprites`（心/鸡腿等）。
- 背包页**补上玩家自己 36 格**，这样"给女仆穿装备"不必先丢地上再让她捡。
- `MaidControlScreen` 重写为 `MaidMenuScreen extends Screen`；`MaidControlMenu`/`MAID_CONTROL_MENU` 保留注册（不破坏旧引用），但不再作为主入口。
- 旧 `MaidCommandPayload(int action)` 只保留非指令动作（`OPEN_INVENTORY` / `RECALL`），指令类全部迁到 `MaidMenuCommandPayload{cmd,paramsJson}`。
